# 성능 벤치마크

모든 수치는 아래 환경에서 실제로 측정했습니다. 노트북이므로 전원 상태·배경 부하에 따라 달라질 수 있습니다(같은 조건에서 두 번 측정한 차이는 엔진 수치 ±3% 이내, MPC 결정 시간은 0.31 ↔ 0.40 ms). 원본: [`public/data/benchmark.json`](../public/data/benchmark.json) — `npm run benchmark` 로 다시 측정합니다.

| 항목 | 값 |
|---|---|
| CPU | Intel Core Ultra 7 256V (8코어), 메모리 16 GB, GPU 사용 안 함 |
| OS / 런타임 | Windows 11 (10.0.26200), Node v24.19.0, Python 3.12.10, PyTorch 2.14.1 (CPU) |
| 측정일 | 2026-10-21 |

## 엔진 (Node, 단일 스레드, 무작위 조향, `world.step()`만 측정)

| 지렁이 수 (L = 400) | ms/틱 | 틱/s |
|---|---|---|
| 5 | 0.129 | 7,750 |
| 10 | 0.197 | 5,080 |
| 20 | 0.321 | 3,120 |
| 30 | 0.411 | 2,430 |
| 50 | 0.580 | 1,720 |

| 몸 길이 (20마리) | 몸통 꼭짓점 합 | ms/틱 |
|---|---|---|
| 240 | 800 | 0.249 |
| 1,000 | 3,340 | 0.738 |
| 3,000 | 10,000 | 1.877 |
| 6,000 | 20,000 | 3.089 |

비용은 꼭짓점 수에 대략 선형입니다. 충돌 단계만 따로 재면(20마리, L = 1000, 선분 3,340개) 공간 해시 재구성 0.17 ms + 사망 판정 0.009 ms이며, 틱당 하위 스텝 2회 × 재구성이 주된 비용입니다. 실시간 게임(30 Hz, 지렁이 15–25마리)은 한 틱 1 ms 미만이므로 배속 상한의 대부분은 AI 결정과 렌더링이 차지합니다.

## AI 결정 시간 (15마리 경기장, 결정 1회)

| 정책 | ms |
|---|---|
| Random | < 0.001 |
| Potential Field | 0.012 |
| Greedy | 0.017 |
| Aggressive | 0.030 |
| MPC-lite (깊이 1, 18 궤적) | 0.061 |
| Hybrid (18 궤적 안전 검사) | 0.067 |
| Survival (센서 16 광선 포함) | 0.155 |
| **MPC (깊이 2, 90 궤적)** | **0.307** |
| 관측 생성 (센서 + obs-v1 인코딩) | 0.157 |
| MLP 추론 (84→256→256→18, TypeScript) | 0.067 |

MPC 결정 시간은 주변 상황에 따라 달라지며, 관전 화면의 분석 패널에 매 결정의 실제 계산 시간이 표시됩니다.

## 화면 인식과 제어 루프

| 항목 (960×720 캔버스) | 값 |
|---|---|
| 고전 CV 인식 | 평균 35–44 ms/프레임 (검증 세트) |
| CNN 인식 (TinyUNet, CPU, 4 스레드) | 평균 350–380 ms/프레임 |
| 캔버스 캡처 (Playwright PNG) + 디코딩 | 약 43 ms |
| 정책 추론 (NumPy) | 약 2.6 ms |
| 전체 제어 주기 (실시간) | 측정값은 [`EXPERIMENTS.md`](EXPERIMENTS.md) §Sim-to-Visual |

CNN은 고전 CV보다 약 10배 느려 실시간 10 Hz 제어 루프에 쓰기 어렵습니다. 실제 Vision Bridge 실행은 고전 CV를 씁니다.

## 브라우저

렌더 FPS와 시뮬레이션 UPS는 관전 화면 분석 패널의 "성능" 항목에 실시간으로 표시됩니다(측정값은 기기마다 다르므로 문서에 고정하지 않음). 시뮬레이션은 Web Worker에서 돌고, 렌더링은 메인 스레드의 requestAnimationFrame에서 최신 프레임을 그립니다.
