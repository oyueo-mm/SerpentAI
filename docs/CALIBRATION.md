# Calibration

시뮬레이터의 예측(정확한 엔진 상태)과 실제 브라우저에서 화면으로 관측한 값을 같은 타임라인에 놓고 비교합니다. 같은 엔진을 쓰더라도 화면 인식과 조작 지연 때문에 오차가 생기며, 그 크기를 측정해 Sim-to-Visual 실험의 조건 B(지연)와 C(관측 잡음)를 정합니다.

## 기록 (한 타임라인, 같은 기계의 epoch ms)

| 출처 | 기록 | 언제 |
|---|---|---|
| Vision Runner (`log.jsonl`) | 캡처 시각, 캡처·인식·정책·입력 시간, 인식 결과(배율, 방향, 머리 목록, 먹이 수, HUD), obs-v1, 행동, 행동 확률, 입력 전송 시각 | 매 제어 스텝 |
| 게임 페이지 (`?gt=1`, `groundtruth.json`) | 틱별 엔진 상태(자기·주변 지렁이·먹이·정확한 Sensors와 obs-v1, 그 틱에 적용된 입력 번호), 입력 수신 시각, 그려진 틱과 카메라·시각 | 매 틱 / 매 입력 / 매 그리기 |

Ground Truth는 **실행이 끝난 뒤** 한 번만 읽고 평가·Calibration에만 씁니다. 실행 중의 Vision AI 결정에는 전달되지 않습니다(`GuardedPage`, 테스트).

## 정렬

- 캡처 시각 → 그 시각에 화면에 그려져 있던 틱(그리기 기록의 마지막 항목) → 그 틱의 엔진 상태와 정확한 obs.
- 입력 전송 시각 → 페이지의 입력 수신 시각(같은 순번) → 그 입력이 처음 적용된 틱 → 그 틱이 그려진 시각.

## 측정 항목 ([`vision/calibration/analyze.py`](../vision/calibration/analyze.py))

| 항목 | 정의 |
|---|---|
| 방향 오차 | 인식한 자기 방향 vs 엔진 진행 방향 |
| 배율 오차 | 격자 주기로 추정한 px/u vs 카메라 배율 |
| 길이 오차 | HUD 게이지로 읽은 길이 vs 엔진 길이 |
| 상대 머리 위치·방향 오차 | 눈 쌍 머리 vs 엔진 머리(화면 좌표 변환) |
| 이동·회전 속도 오차 | 시각 주행거리로 잰 카메라 속도·방향 변화율 vs 엔진 속도·각속도 |
| 관측 오차 | 인식 obs-v1 vs 정확한 obs-v1 (직전 행동 특징은 러너 자신의 값으로 맞춤), 특징별·그룹별 MAE |
| 행동 일치율 | 같은 정책이 인식 obs에서 고른 행동 vs 정확한 obs에서 고를 행동 |
| 표시→캡처 지연 | 캡처 시각 − 그 틱이 그려진 시각 |
| 입력 지연 | 전송 → 페이지 수신 → 적용 틱 → 그려짐 |
| 처리 시간 | 캡처, 인식, 정책, 입력 |
| 몸통 IoU, 먹이 재현율 | 합성 검증 세트의 라벨 렌더 기준 (실시간 세션에는 라벨이 없음 — [`VISION.md`](VISION.md)) |

**오차가 큰 상황 자동 수집**: 각 스텝을 교차(두 지렁이가 가까이 겹침), 화면 가장자리의 머리, 부스트 중 급회전, 먹이 밀집, 직후 사망 발생으로 분류하고 상황별 관측 MAE를 비교합니다.

**오프라인 보정** ([`vision/calibration/fit.py`](../vision/calibration/fit.py)): 먹이 반경 편향을 학습 세트의 먹이 41,505개(GT와 2 px 이내로 짝지어진 것만)로 측정해 `vision-calibration.json`에 저장합니다. 측정 중앙값은 −0.05 px (IQR −0.12 … +0.01) 이었고, 처음 넣었던 가정값 +0.25 px는 먹이 합을 약 25% 과대추정하게 만들어 교체했습니다.

## 결과 (Sim-to-Visual v2, 실시간 세션 8개 = 조건 E)

| 항목 | 값 |
|---|---|
| 자기 방향 오차 | 중앙값 3.0° (록스텝 0.8°) |
| 배율 오차 | 0.05% |
| HUD 길이 오차 | 1.2% |
| 상대 머리 위치 오차 | 3.1 u (록스텝 1.0 u) |
| 관측 MAE (몸통 광선 / 벽 광선 / 먹이 합 / 먹이 거리 / 상대) | 0.0044 / 0.0026 / 0.026 / 0.033 / 0.013 |
| 행동 일치율 | 62.4% |
| 화면 표시 → 캡처 | 17.6 ms |
| 캡처 + 인식 + 정책 + 입력 | 34.2 + 39.1 + 2.2 + 11.5 = 87.0 ms/스텝 (9.7 Hz) |
| 입력 전송 → 페이지 수신 → 적용 틱 | 11.3 ms → +28.8 ms |
| 화면 → 행동 적용까지 합 (조건 B에 사용) | 133 ms ≈ 4틱 |
| 관측 잡음 등가 σ (조건 C에 사용) | 0.020 (= 광선·먹이·상대 MAE 평균 × √(π/2)) |

**오차가 큰 상황** (스텝별 관측 MAE 평균): 교차 0.0375 (7 스텝) > 먹이 밀집 0.0167 (18) > 사망 직후 0.0137 (94) > 화면 가장자리 0.0128 (917) > 일반 0.0117 (3,181). 두 지렁이가 겹쳐 지나갈 때 오차가 일반 상황의 3배이지만 표본이 매우 적습니다.

**특징별 분석이 평균보다 중요했습니다.** v1의 평균 관측 MAE는 작았지만(상대 그룹 0.014), 상대 속도 특징 하나가 +0.81 편향되어 있었고 이것이 shift 테마에서 정책 붕괴를 일으켰습니다 ([`EXPERIMENTS.md`](EXPERIMENTS.md#발견-상대-속도-특징의-편향-v1--v2)). 특징별 MAE는 [`public/data/vision/calibration.json`](../public/data/vision/calibration.json)의 `perFeature`에 있습니다.
