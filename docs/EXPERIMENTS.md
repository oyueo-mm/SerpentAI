- **단독 평가와 경기장 평가의 순위가 다릅니다.** Survival은 단독 9.1(5위)이지만 24마리 난전에서는 사망률 75%로 9위입니다. 상대 구성에 따라 강함이 달라지므로 두 결과를 모두 봐야 합니다.

## Q2. 모방학습이 PPO의 학습 효율을 개선하는가?

세 변형은 스텝 예산(2,035,712 실제 스텝), 커리큘럼, 롤아웃 시드, 하이퍼파라미터, 관측 정규화가 같고 초기 정책만 다릅니다 ([`REINFORCEMENT_LEARNING.md`](REINFORCEMENT_LEARNING.md)). **학습 시드는 변형당 1개**입니다.

### 답

- **초기 학습 효율은 분명히 개선됩니다.** 10만 스텝에서 검증 리턴 0.4 → 5.7(BC) / 7.1(DAgger). 무작위 초기화가 100만 스텝에 도달한 수준(10.7)을 BC·DAgger 초기화는 30만 스텝 안팎에 넘었습니다.
- **최종 성능 차이는 작고 불확실합니다.** 최종 리턴은 DAgger > BC > Random 순이지만 CI가 겹칩니다(DAgger [13.05, 15.76] vs Random [11.46, 13.49]). 그리고 지표에 따라 순위가 뒤집힙니다: 무작위 초기화 PPO가 **더 오래 살고 덜 죽는** 대신, 모방 초기화 PPO는 **더 길게 자라고 더 많이 처치**합니다 — 전문가(MPC)의 공격적 먹이 수집 습관이 PPO 이후에도 남은 것으로 보입니다. 리턴(reward-v1)은 길이 증가를 크게 보상하므로 모방 초기화 쪽이 높습니다.
- **혼입 요인**: Supervisor가 PPO-BC(2회)와 PPO-DAgger(3회)에서는 학습률을 줄였지만 PPO-Random에서는 줄이지 않았습니다. 개입도 알고리즘의 일부지만, 학습률 일정이 같지 않았다는 점은 결과 해석에 영향을 줍니다. 학습 시드 1개라 시드 간 분산도 모릅니다.
- **DAgger 초기화 vs BC 초기화**: 처음 20만 스텝은 DAgger가 앞서고 최종 리턴도 약간 높지만, 통계적으로 구분되지 않습니다. 모방학습 단계에서는 DAgger r2가 BC보다 확실히 나았는데(생존 84.5 vs 49.7 s), PPO 미세조정 후에는 그 차이가 대부분 사라집니다.

### Supervisor 기록

세 실행 모두 이상 징후(제자리 회전, 벽 붙기, 무의미한 부스트, 먹이 무시, 비현실적 보상률, 정면 충돌 남용, 행동 붕괴)는 탐지되지 않았습니다. 개입: PPO-Random — 경고·보존 4회, 학습률 축소 0회 / PPO-BC — 경고·보존 6회, 학습률 축소 2회 (50만, 170만 스텝) / PPO-DAgger — 경고·보존 7회, 학습률 축소 3회 (50만, 120만, 190만 스텝). 복귀(rollback)는 일어나지 않았습니다. 모든 실행의 커리큘럼 관문이 첫 시도에 통과했습니다.

### 답

- **Q3 — 그렇다, 시간 조건이 같다면.** 엔진 상태로만 학습한 정책이 화면 픽셀만으로 플레이한 록스텝 조건(D)의 성능은 정확한 상태(A)와 구분되지 않습니다 (생존 81.2 vs 84.5 s, 짝지은 차이 −3.3 s [−35, 28], 최대 길이 1217 vs 1210). 이때 관측 오차는 몸통 광선 MAE 0.0025(≈ 1 u), 자기 방향 0.8° 수준입니다.
- **Q4 — 실시간 제어에서 성능이 크게 떨어지지만, 단일 원인으로 설명되지 않습니다.** E는 생존 54.3 s, 8판 모두 사망, 최대 길이가 절반(672)입니다. 그런데 E에서 측정한 지연만 넣은 B(76.0 s)와 측정한 잡음만 넣은 C(94.0 s)는 A와 거의 같습니다. 민감도 곡선에서도 지연 6틱(200 ms)·잡음 σ 0.05까지는 뚜렷한 저하가 없고 9틱(300 ms)·σ 0.1부터 떨어집니다. 실시간에서만 생기는 요인 — 움직이는 화면에서의 큰 방향 오차(0.8° → 3.0°)와 상대 위치 오차(1.0 → 3.1 u), 결정 사이에 목표 방향에 도달하면 회전을 멈추는 마우스 입력 방식(act-v1과 의미가 다름), 프레임 간격의 흔들림 — 이 함께 작용하는 것으로 보이며, 이 실험만으로는 분리하지 못했습니다.
- **실시간 결과의 분산이 큽니다.** 같은 시드·같은 코드로 E를 두 번 실행한 결과(v1 관측기 77.8 s, v2 관측기 54.3 s)의 차이가 신뢰구간 안에 있습니다. 실시간 실행은 타이밍이 매번 달라 경기 진행 자체가 갈라지므로, 8 에피소드로는 조건 간 작은 차이를 판정할 수 없습니다.
- **시각적 도메인 변화(F)는 가장 큰 저하 요인입니다** (짝지은 차이 −43.5 s, CI가 0을 포함하지 않음). 오프라인 검증 세트에서는 shift 테마의 정확도가 오히려 좋았지만(방향 0.72°, 머리 재현율 1.00), 실제 플레이에서는 상대 머리 위치 오차가 2배(6.3 u), 두꺼운 몸통 때문에 몸통 광선 오차가 2배가 됩니다. 정지 프레임 정확도가 제어 성능을 보장하지 않습니다.

### 발견: 상대 속도 특징의 편향 (v1 → v2)

첫 실행(v1)에서 F 조건이 붕괴했습니다(생존 17.4 s, 8/8 사망, 시드 930004에서는 1.5 s). 오차를 특징별로 나눠 보니 원인은 평균 MAE에 묻힌 **상대 속도 특징**이었습니다: 추적한 속도 벡터의 크기를 그대로 쓰면, 몇 u의 머리 위치 잡음이 0.1 s 간격에서 수십 u/s로 증폭되어 항상 양의 방향으로 편향되고(크기의 Rayleigh 편향), 순항 중인 상대가 부스트 중으로 보였습니다 (특징 편향 +0.81, 상대가 보이는 스텝 기준). 먼저 의심한 몸통 두께·그림자는 원인이 아니었습니다 — 두께 1.0·그림자 없는 shift 변형(`shift-thin`)에서도 생존 14.5 s로 같았습니다([`theme-diagnostic.json`](../public/data/vision/theme-diagnostic.json)).

v2는 속도를 눈으로 잡은 진행 방향에 투영한 뒤 순항(150) 또는 부스트(300)로 분류합니다(지렁이는 진행 방향으로만, 두 속도로만 움직임). 편향은 +0.81 → +0.31로 줄었고 F 생존은 17.4 → 40.9 s가 되었지만, 남은 편향(순항 상대의 약 3분의 1을 여전히 부스트로 읽음)은 해결하지 못한 한계로 남깁니다. 위 표는 v2 결과입니다.

| 부스트 비용 회피 (자기 부스트 먹이 재섭취) | 불가 — 회수량 ≤ 손실의 50% (드롭 비율 그대로) |
| 먹이 중복 섭취 | 없음 — 3 시드 × 900 틱 × 16마리, 매 틱 질량 보존식이 1e-6 이내로 성립 |
| 몸통 충돌 누락 | 없음 — 하위 스텝으로 관통 불가, 하위 스텝을 끄면 관통이 생김을 확인 |
| 특정 각도 벽 관통 | 없음 — 12개 접근 각도 × 부스트 |
| 충돌 처리 순서 악용 | 사망·원인·처치자는 지렁이 번호와 무관. **번호에 의존하는 것 2가지를 문서화**: 정확히 같은 거리의 먹이 동률은 작은 id가 가져감(연속 위치에서는 확률 0), 사망 먹이 위치 잡음의 난수 소비 순서. 둘 다 에이전트가 고를 수 없음 |
| 제자리 무한 회전 | 생존 보너스 이상의 보상 없음 (테스트) + Supervisor 탐지기 |
| 사망 직전 보상 | 사망 스텝 보상은 −1 + 그 스텝 길이 변화뿐, 에피소드 종료 |
| 경기 종료·재시작 | 학습자 사망 = 종료, 120초 = 절단(부트스트랩). 재시작으로 얻는 보상 없음 |
| 특정 상대 악용 | 학습하지 않은 상대 구성(mpc-heavy, swarm)에서도 PPO 성능 유지 (위 표). Supervisor의 상대 특이성 탐지기도 발동하지 않음 |

학습 중 비현실적 보상률(결정당 > 0.12) 경보도 한 번도 울리지 않았습니다. **rules-v1에서 규칙 버그로 인한 악용은 발견하지 못했으므로 규칙 버전을 올리지 않았습니다.**

## 개발 중 발견하고 고친 버그

| 버그 | 발견 방법 | 영향과 조치 |
|---|---|---|
| Supervisor 콜백이 커리큘럼 단계마다 다시 만들어질 때 검증이 몰려서 실행됨 | PPO 로그에서 연속 검증 확인 | 변형 간 학습 조건이 달라질 수 있어 **PPO 3종을 처음부터 다시 학습**. 회귀 테스트 추가 |
| Supervisor 로그에 `step` 키 중복 | 단위 테스트 | 수정 |
| RNG 상태가 음수로 직렬화됨 (값은 같음) | 저장/복원 테스트 | 부호 없는 정수로 정규화 |
| 센서의 먹이 합이 격자 순서에 의존 (부동소수 합산 순서) | 코드 검토 | id 순 합산 |
| 데이터 생성이 부하 상황에서 틱 경합으로 0장 저장 | 데이터 생성 로그 | 워커가 멈출 때까지 대기 후 캡처 |
| CNN이 자기/상대 몸통을 구분 못 함 (검증 IoU 0.006) | 학습 중 검증 IoU | 설계 변경: CNN은 "몸통" 한 클래스, 자기/상대는 화면 중앙 색 클래스로 분리 |
| 격자 주기 정밀화가 노이즈에서 발산 → 배율 폭주 | 증강 검증 세트에서 메모리 오류 | 정밀화 범위 제한 + 카메라 규칙으로 배율 제한 |
| Vision 관측기의 상대 속도 특징이 크게 양의 방향으로 편향 (실시간 shift 테마에서 정책 붕괴) | Sim-to-Visual v1 특징별 오차 분석 | 진행 방향 투영 + 순항/부스트 분류 (v2), 회귀 테스트. 편향 +0.81 → +0.31 |
| 먹이 반경 보정값(+0.25 px)이 오히려 과대추정 | 학습 세트 41,505개 먹이로 Calibration | 측정 중앙값 −0.05 px로 교체 |
| 평가에서 시야 밖 머리를 오검출로 셈 | 오검출 위치 분석 | Ground Truth가 완전한 영역에서만 정밀도 계산 |
| 모바일에서 설정·분석 패널이 겹쳐 조작 불가 | Playwright 모바일 테스트 | 좁은 화면에서 서랍 하나만 열림 |
