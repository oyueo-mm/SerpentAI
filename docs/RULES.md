# 게임 규칙 — `rules-v1`

모든 규칙 상수는 [`src/sim/config.ts`](../src/sim/config.ts)의 `DEFAULT_RULES` 한 곳에 있습니다. 결과를 바꾸는 상수를 수정하면 `RULES_VERSION`을 올려야 하며, 서로 다른 규칙 버전의 점수는 직접 비교하지 않습니다 (저장 파일·모델 파일은 규칙 버전이 다르면 불러오기를 거부합니다).

## 단위

| 양 | 단위 | 비고 |
|---|---|---|
| 좌표·길이·반경 | u (월드 단위) | 경기장은 `[0, 3000]²` 정사각형 |
| 시간 | s | 고정 틱 30 Hz (`dt = 1/30 s`), 렌더링 FPS와 무관 |
| 각도 | rad | 화면 좌표계(y 아래 방향). 진행 방향 θ의 단위 벡터 = (cos θ, sin θ). **+회전 = 화면에서 시계 방향(오른쪽)** |
| 몸 길이 L | u (몸통 경로의 호 길이) | 점수 = ⌊L⌋. 질량 대신 길이를 직접 상태 변수로 씀 |

## 지렁이

| 상수 | 값 |
|---|---|
| 기본 속도 / 부스트 속도 | 150 u/s / 300 u/s |
| 최대 각속도 ω_max (부스트 여부와 무관) | 3.2 rad/s → 최소 회전 반경 47 u (부스트 시 94 u) |
| 시작 길이 / 최소 길이 / 부스트 가능 최소 길이 | 240 / 120 / 160 u |
| 몸통 반경 r(L) | `min(30, 10·(L/240)^0.35)` u — 길이 120에서 7.8, 1000에서 16.5, 3000에서 24.2 |

**입력.** 매 틱 `turn ∈ [-1, 1]`(ω_max의 비율) 또는 `targetHeading`(목표 방향, 한 틱에 최대 ω_max·dt만큼 회전)과 `boost`. 입력이 없으면 직진·부스트 없음. 정책은 결정 주기(기본 3틱 = 10 Hz) 사이에 마지막 명령을 유지합니다 ([`src/sim/match.ts`](../src/sim/match.ts)).

**이동.** 각 틱을 고정 개수의 하위 스텝(`ceil(부스트 속도·dt / 5 u)` = 2)으로 나누고, 각 하위 스텝에서 머리를 **정확한 원호**로 적분합니다 (`integrateArc`). 같은 회전 명령이면 틱 간격과 무관하게 같은 궤적이 나옵니다.

**몸통.** 확정된 꼭짓점(꼬리 → 머리 방향) + 현재 머리점으로 이루어진 폴리라인입니다.
- 머리가 마지막 꼭짓점에서 6 u 이상 떨어지면 머리 위치를 새 꼭짓점으로 확정합니다 (틱 수가 아니라 이동 거리 기준).
- 경로 호 길이가 L을 넘으면 꼬리 꼭짓점을 선분 위에서 정확히 잘라 길이를 L로 맞춥니다.
- 길이가 늘면 꼬리가 멈춘 채로 머리가 전진하여 늘어난 만큼을 채웁니다 (몸통 일부가 순간이동하지 않음).
- 확정 선분 길이 ≤ 6 + 5 u, 목 선분 < 6 u가 항상 성립합니다 (테스트로 검증).

## 먹이와 성장

- 자연 먹이: 개수가 목표(1200)보다 적으면 틱당 최대 4개 생성, 값 2–6 (정수, 균등), 위치 균등.
- 먹이 반경 `2 + 1.2·√value` u. 입의 도달 범위 = 머리 반경 + 먹이 반경 + 6 u.
- **흡수 판정은 하위 스텝 동안 머리가 지나간 선분** 기준(먹이 건너뛰기 없음). 한 먹이를 여러 머리가 동시에 노리면 가장 가까운 머리, 거리가 같으면 id가 작은 쪽이 먹습니다. 흡수 순서는 먹이 id 순.
- 먹은 값만큼 L이 즉시 증가.

## 부스트

- `L > 160`일 때만 적용. 속도 300 u/s, 비용 45 u/s (하위 스텝 단위로 차감), 길이는 160 아래로 내려가지 않습니다.
- 잃은 길이의 50%가 누적되어 6 u마다 꼬리 위치에 먹이(값 6)로 떨어집니다 → 부스트의 순손실은 최소 50% (자기 먹이를 다시 먹는 방식으로 비용을 피할 수 없음).

## 충돌과 사망 (하위 스텝마다, 이동 후 한 번에 판정)

1. **벽**: 머리 원(반경 r)이 경기장 경계에 닿으면 사망.
2. **정면 충돌**: 두 머리가 하위 스텝 동안 연속 최근접 거리 < r_i + r_j로 접근하면 정면 충돌. **더 짧은 쪽이 사망**(긴 쪽에 처치 기록), 길이가 같으면 **둘 다 사망**(처치 기록 없음). 정면 충돌 쌍 사이의 몸통 충돌은 무시.
3. **몸통 충돌**: 머리 원이 다른 지렁이 몸통 캡슐(폴리라인의 각 선분, 반경 r_j)과 겹치면 사망. 처치는 가장 깊이 파고든 몸통의 주인(같으면 id가 작은 쪽).
4. **자기 몸통 충돌 없음** (rules-v1).
5. 모든 사망은 같은 이동 후 상태에서 결정된 뒤 **동시에** 적용됩니다 → 처리 순서와 무관한 결정론적 결과. 사망 원인 우선순위: 정면 > 몸통 > 벽.
6. 이번 하위 스텝에 죽는 지렁이는 먹이를 먹지 않습니다.

**관통 방지.** 하위 스텝당 머리 이동은 5 u 이하이고, 가장 가는 두 몸체의 접촉 거리 합은 15.6 u 이상이므로 이산 겹침 검사로 교차를 놓칠 수 없습니다. 이 근거는 테스트로 확인합니다: 하위 스텝을 끈 상태에서 2400 u/s로 달리면 관통이 실제로 발생하고, 하위 스텝을 켜면 48가지 위상·각도 모두에서 충돌이 검출됩니다 ([`src/sim/world.test.ts`](../src/sim/world.test.ts)).

## 사망 후 먹이

죽은 지렁이 길이의 60%를 머리에서 꼬리 방향으로 `max(8, r)` u 간격의 먹이로 나눠 떨어뜨립니다 (위치에 ±r/2의 결정론적 잡음).

## 경기 진행

- 관전·플레이 모드: AI는 사망 2초 뒤 안전한 위치(벽에서 300 u 이상, 다른 몸통에서 가장 먼 후보)에 부활합니다.
- 토너먼트: 부활 없음, 90초 또는 한 마리만 남으면 종료. 순위 = 생존자는 길이순, 사망자는 오래 버틴 순.

## 결정론과 재현

- 모든 무작위성은 시드에서 파생된 sfc32 스트림(먹이, 부활 위치, 정책별 RNG)을 씁니다.
- 반복 순서는 항상 id 순이고, 동률은 id로 깨며, 부동소수 합산 순서도 고정했습니다(먹이는 id 순으로 합산).
- 같은 시드 + 같은 입력 → 비트 단위로 같은 상태. 저장 → 복원 → 계속 진행도 비트 단위로 같습니다.
- 다른 언어 구현(Python 참조 엔진)과는 위치 1e-6 u, 보상 1e-9 허용 오차로 일치합니다 ([`docs/TESTING.md`](TESTING.md)).
