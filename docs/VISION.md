# 화면 인식과 Vision Bridge

목표: 엔진 상태를 전혀 받지 않고, **렌더링된 화면 픽셀만으로** obs-v1을 추정해 같은 정책을 실행하는 것.

```
Chromium 창 (?view=target)          Python Vision Runner (vision/bridge/runner.py)
┌──────────────────────┐  PNG     ┌───────────────────────────────────────────────────────┐
│ 게임 캔버스 + HUD     │ ───────▶ │ detect() → VisionObserver → obs-v1 → MLP (같은 JSON)  │
│ (공식 입력만 받음)    │ ◀─────── │ 회전 단계 → 포인터 위치, 부스트 → Space 키              │
└──────────────────────┘ 마우스/키 └───────────────────────────────────────────────────────┘
```

## 화면 설계 (인식이 기대는 규칙)

렌더러([`src/render/renderer.ts`](../src/render/renderer.ts))가 지키는 공개 규칙입니다. 게임 디자인의 일부이며 숨은 상태가 아닙니다.

- 카메라는 자기 머리를 화면 정중앙에 두고 **회전하지 않으며**, 짧은 변 기준으로 머리 주변 480–600 u를 항상 보여 줍니다.
- 경기장 바닥에 100 u 간격 격자, 경기장 밖은 단색 벽.
- 지렁이는 채도가 높은 색 + 어두운 외곽선, 머리에 흰 눈 두 개(진행 방향 기준 앞쪽 0.38r, 양옆 0.46r). 먹이는 작은 원.
- HUD: 캔버스 왼쪽 아래 고정 위치에 길이 게이지(로그 눈금, 120–12,000 u)와 부스트 가능 표시점.

## 고전 CV 파이프라인 ([`vision/detection/classical.py`](../vision/detection/classical.py))

| 단계 | 방법 |
|---|---|
| HUD | 게이지 행의 채움 색 비율 → L = 120·100^f, 표시점 색 → 부스트 가능 |
| 채색 마스크 | HSV 채도 > 90, 명도 > 40 (배경·벽·그림자·부스트 광채는 저채도) |
| 벽 | 바닥보다 어두운 저채도 픽셀을 5×5 열림 연산(격자선 제거) → 열/행별 비율이 60%를 넘는 화면 가장자리 구간 = 경기장 사각형 밖 |
| 배율 | 바닥 픽셀의 열/행 밝기 프로파일 자기상관 → 격자 주기 P(부분 픽셀) → z = P/100. 탐색 범위는 화면 크기에서 카메라 규칙으로 계산 |
| 색 클래스 | 채색 픽셀 색상 히스토그램의 봉우리마다 클래스, 각 픽셀은 가장 가까운 봉우리 |
| 먹이 / 몸통 | 클래스별 연결 요소: 크기·둥근 정도가 먹이 상한(값 20 기준 반경) 이하이고 주변이 거의 비채색(적분 영상으로 확인)이면 먹이, 아니면 몸통 |
| 자기 몸통 | 화면 중앙의 색 클래스 |
| 머리 | 채색 마스크 속 **닫힌 구멍** = 눈(+눈동자). 크기가 비슷하고 1.6–4.5배 반경 거리인 구멍 쌍 → 머리. 눈 축의 수직 방향 중 몸통 픽셀이 많은 쪽이 뒤 |
| 자기 방향 | 중앙에 가장 가까운 눈 쌍. 없으면 목 방향(머리 뒤 고리 영역의 자기 몸통 픽셀 평균의 반대) — 신뢰도 낮춤 |

## 관측 변환 ([`vision/observation/from_vision.py`](../vision/observation/from_vision.py))

- 몸통 광선: 다른 몸통 마스크를 따라 1 px씩 진행, 첫 픽셀까지 거리 / z.
- 벽 광선: 화면 사각형과의 교차 / z.
- 먹이: 원 → 자기 중심 좌표 → 섹터, 값 = ((r/z + 보정 − 2)/1.2)².
- 상대: 눈 쌍 머리 → 자기 중심 좌표, 상대 방향(눈), 반경(거리 변환), 속도(칼만 추적).
- 자기 길이·부스트: HUD. 직전 행동: 러너 자신의 기억.
- 신뢰도 = (0.5 + 0.5·격자 신뢰도) × (눈 1.0 / 목 0.6 / 없음 0.2) × (HUD 있음 1.0 / 없음 0.8), 프레임 나이 = 캡처 후 경과 시간.

## 추적 ([`vision/tracking/tracker.py`](../vision/tracking/tracker.py))

카메라 이동은 격자 위상 변화로 측정합니다(시각 주행거리, [`MATHEMATICS.md`](MATHEMATICS.md) §6). 상대 머리는 그 좌표계에서 등속 칼만 필터로 추적하며, 거리 70 u·색상 18 단위 안에서 최근접 매칭합니다. 4 프레임 연속 미검출이면 소실. 새 트랙은 눈 방향·순항 속도로 초기화하고, 3번 이상 매칭된 트랙의 속도만 관측에 씁니다. 가려진 동안은 예측으로 유지됩니다(테스트: 2 프레임 가림 후에도 같은 트랙, 300 u/s ±10%).

## 학습형 비전 ([`vision/segmentation/cnn.py`](../vision/segmentation/cnn.py))

- **데이터**: [`vision/datagen.py`](../vision/datagen.py)가 실제 게임 페이지에서 같은 틱을 두 번 렌더링합니다 — 일반 테마와 **라벨 테마**(같은 기하, 클래스별 단색: 바닥·벽·자기·상대·먹이·눈). 같은 틱의 엔진 상태(카메라, 머리, 먹이, Sensors, obs)를 함께 저장합니다. 게임은 `]` 키로 록스텝 진행해 프레임과 정답이 항상 같은 틱입니다.
- **도메인 무작위화**: 배경색·채도, 격자 대비, 벽색, 지렁이 팔레트(색상 회전, 채도·명도), 외곽선 진하기, 몸통 두께(0.9–1.1배), 그림자, 먹이 색, 화면 크기 5종(→ 배율 변화). 학습 시 밝기·대비, 가우시안 잡음, JPEG 압축(품질 45–90), 부분 가림(가린 영역은 손실에서 제외)을 추가합니다.
- **분할**: 학습 = 무작위 테마 시드 1000–1023, 검증 = 무작위 테마 시드 5000–5004(겹치지 않음), 기본 테마, 그리고 **학습에 전혀 쓰지 않은 'shift' 테마**(따뜻한 배경, 다른 팔레트, 두께 1.12, 그림자).
- **모델**: TinyUNet (채널 12-24-48-64, 완전 합성곱, 전체 해상도 추론), 클래스 가중 교차 엔트로피(눈 6, 먹이 3), 192×192 크롭 절반은 눈 주변에서, AdamW + OneCycle.
- CNN은 채색 규칙 대신 마스크를 만들고, 배율(격자)·HUD·기하 단계는 고전 파이프라인과 같은 코드를 씁니다. 두 방식은 같은 `Detections` 계약을 따릅니다.

## Vision Bridge 안전 장치 ([`vision/bridge/runner.py`](../vision/bridge/runner.py))

| 상황 | 동작 |
|---|---|
| 대상 주소가 로컬 SerpentAI 빌드 또는 `oyueo-mm.github.io/SerpentAI/`가 아님 (시작 시 + 매 스텝) | 즉시 정지 |
| 게임 영역/자기 지렁이 미검출 8 프레임 연속 | 정지 (그 사이에는 부스트 해제) |
| 관측 신뢰도 < 0.3이 10 프레임 연속 | 정지 |
| 프레임 캡처 실패 또는 1.5초 초과 | 정지 |
| 제어 스텝 400 ms 초과가 5회 연속 | 정지 |
| GAME OVER (화면이 어두워지고 인식 실패) | 정상 종료 |
| Ctrl+C, `vision/EMERGENCY_STOP` 파일, 제어 엔드포인트 `/stop`·`/estop` | 정지 / 비상 정지 |

정지할 때는 항상 Space 키를 놓습니다(테스트로 누름·뗌 횟수 일치 확인). 웹의 화면 인식 실험실 패널에서 `--wait-start`로 대기 중인 러너를 Start/Stop/Emergency Stop 할 수 있습니다(127.0.0.1:8765, 사용자가 "연결"을 눌렀을 때만 요청).

**상태 누출 방지.** 제어 루프는 `GuardedPage`만 받습니다: 캔버스 캡처, 포인터 이동, 키 누름, URL, 캔버스 위치만 허용하고 나머지 속성 접근(`evaluate` 등)은 `GuardViolation`을 던집니다. 게임 페이지는 `?gt=1`일 때만 Ground Truth 기록을 만들고, Calibration 기록기는 **루프가 끝난 뒤** 한 번 읽습니다. 테스트가 가짜 페이지로 루프를 돌려 `evaluate` 호출이 전혀 없음을 확인합니다.

## 실행

```bash
npm run build && npm run preview                         # http://127.0.0.1:4173/SerpentAI/
python -m vision.bridge.runner --model public/models/ppo-dagger-v1.json --headed            # 실시간
python -m vision.bridge.runner --model … --mode lockstep --record vision/sessions/demo --gt-record
python -m vision.datagen --out vision/datasets/train --episodes 24 --frames 50 --theme rand
python -m vision.segmentation.cnn train --data vision/datasets/train --val vision/datasets/val-rand
python -m vision.report                                    # 고전 vs CNN 정확도 → public/data/vision/accuracy.json
```
