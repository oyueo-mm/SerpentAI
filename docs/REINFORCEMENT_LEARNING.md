# 강화학습 (PPO)

## Python 학습 환경: 방법 A vs 방법 B

| | 방법 A — TypeScript 엔진을 Node로 실행 | 방법 B — Python으로 엔진 재구현 |
|---|---|---|
| 구현 | `rl/bridge/bridge.ts` (esbuild 번들) + `rl/bridge_client.py` (길이 접두 JSON + float32) | `rl/rules_reference.py` (규칙 핵심만, 격자 없음) |
| 정확성 | 브라우저와 **같은 코드** (엔진·센서·obs·보상·상대 AI) | 골든 궤적 3종과 1e-6 u·1e-9 보상으로 일치(테스트) — 단 휴리스틱·MPC·센서는 미포팅 |
| 처리량 (측정) | 엔진만 10마리: 약 10,000 틱/s (0.10 ms/틱, `benchmark.json`). 환경 스텝(3틱 + 상대 결정 + 관측): A-food 22,300 스텝/s, D-mixed 590 스텝/s — 스레드 1개 | 엔진만 10마리, 먹이 1200: **207 틱/s** |
| 복잡도 | 프로세스 간 통신 | 규칙·AI·센서 전부 두 언어로 유지 |

같은 조건(엔진만, 10마리)에서 방법 B가 약 50배 느리고, 상대 AI와 센서까지 포팅하면 두 구현을 계속 일치시켜야 하는 부담이 생깁니다. 그래서 **학습은 방법 A**, 방법 B는 규칙의 독립 검증용(오라클)으로 유지합니다. 병렬화는 브리지 프로세스 여러 개(학습 시 7 × 8 = 56 환경)로 합니다.

PettingZoo Parallel API는 검토만 했습니다. 현재 실험은 학습자 1마리 + 상대 풀(휴리스틱·MPC·자기 스냅샷) 구조이므로 단일 에이전트 Gymnasium/SB3 VecEnv로 충분합니다.

## 환경 (`rl/bridge/envs.ts`, `rl/envs.py`)

- 관측 obs-v1(84), 행동 act-v1(18, 부스트 마스킹), 보상 reward-v1 — [`OBSERVATION_ACTION.md`](OBSERVATION_ACTION.md).
- 결정 1회 = 3틱(0.1 s). 에피소드 = 학습자 사망 또는 1200 결정(120 s). 상대는 2초 뒤 부활.
- 시드: 학습 롤아웃은 900000 미만, 평가 시드는 900000 이상으로 분리 (검증 905000번대, 관문 907000번대, 모방학습 라운드 선택 910000번대, **최종 평가 920000번대**, Sim-to-Visual 930000번대).
- 실험 조건용 옵션: `actionDelay`(틱 단위 지연 큐), `obsNoise`(특징 6–81에 가우시안 잡음), `expert`(방문 상태마다 전문가 레이블), `learnerPolicy`(전문가 롤아웃).
- 행동 통계(에피소드 끝): 이동 거리, 순변위, 방문한 100 u 칸 수, 벽 근처 비율, 제자리 회전 비율, 처치 종류 — Supervisor의 이상 징후 탐지에 사용.

## 알고리즘과 하이퍼파라미터

sb3-contrib **MaskablePPO**, `MlpPolicy` (액터·크리틱 각각 84→256→256, tanh), 56 환경 × 256 스텝 = 롤아웃 14,336, 배치 1,024, 6 에포크, lr 3e-4, γ 0.99, λ 0.95, clip 0.2, 엔트로피 0.01, 가치 계수 0.5, grad clip 0.5, target KL 0.03. 관측 정규화는 전문가 데이터의 평균·분산으로 **고정**(세 변형 동일, 보상은 정규화하지 않음).

## 비교 설계 (Q2)

| 변형 | 초기 정책 |
|---|---|
| PPO-Random | 무작위 초기화 |
| PPO-BC | BC (il-v1 r0) 액터 + 몬테카를로 리턴으로 예열한 크리틱 |
| PPO-DAgger | BC + DAgger r2 (검증 성능 최고 라운드) |

세 변형은 **스텝 예산(2,000,000), 커리큘럼 일정, 롤아웃 시드, 하이퍼파라미터, 관측 정규화가 모두 같고** 초기 정책만 다릅니다. 같은 스텝에서의 비교는 학습 곡선(10만 스텝마다 검증 시드 24개)으로, 최종 성능 비교는 최종 평가(새 시드)로 따로 봅니다. 학습 시드는 변형마다 1개이므로 시드 간 분산은 측정하지 못했습니다 — 결론의 강도는 그만큼 제한됩니다.

## 커리큘럼

| 단계 | 시나리오 | 예산 비율 | 관문 (그 단계 시나리오, 시드 16개) |
|---|---|---|---|
| A | 먹이만 | 8% | 평균 먹은 양 ≥ 150 |
| B | 정적 장애물(천천히 원을 도는 길이 1400의 지렁이 6마리) | 8% | 사망률 ≤ 0.6 |
| C | 움직이는 상대(Random 3, Greedy 3, Potential 1) | 14% | 사망률 ≤ 0.7 |
| D | 혼합 휴리스틱 + MPC-lite (11마리) | 30% | 생존 ≥ 40 s |
| E | 공격적 상대 위주 (9마리) | 15% | 생존 ≥ 35 s |
| F | Self-Play: 휴리스틱 6 + MPC-lite + 자기 스냅샷 2 | 25% | – |

관문을 통과하지 못하면 그 단계를 예산의 10%만큼 한 번 연장하고, 그만큼을 마지막 단계에서 빼서 **총 예산을 같게** 유지합니다.

**Self-Play.** 단계 E 종료 시점과 단계 F 동안 15만 스텝마다 현재 정책을 내보내 상대 풀에 추가하고, 브리지(8 환경 단위)마다 풀에서 서로 다른 스냅샷 2개를 고릅니다. 최신 모델만 상대하지 않도록 휴리스틱·MPC-lite가 항상 함께 있습니다.

## 학습 Supervisor (`rl/supervisor.py`)

- 감시: 리턴, 생존 시간, 사망률, 최대 길이, 부스트 비율, 행동 분포(SB3 로그의 엔트로피·KL·가치 손실은 `logs/progress.csv`).
- 이상 징후: 제자리 회전(최대 회전 연속 비율 > 0.6 이면서 분당 방문 칸 < 4), 벽 붙기(벽 근처 > 35%), 무의미한 부스트, 먹이 무시 생존, 비현실적 보상률(결정당 > 0.12 → 악용 의심), 정면 충돌 규칙 남용(처치의 3/4 이상이 정면), 행동 붕괴(한 행동 > 85%), 상대 특이적 성능(학습 상대/미학습 상대 비 > 1.6).
- 개입: 검증 점수가 최고의 92% 아래로 떨어지면 경고 + 현재 체크포인트 보존 → 2회 연속이면 학습률 ×0.5, target KL ×0.5 → 그 뒤에도 2회 더 나쁘면 최고 검증 체크포인트로 복귀. 모든 결정을 이유와 함께 `supervisor.jsonl`에 기록합니다.
- 최종 배포 모델은 마지막 체크포인트가 아니라 **검증 점수가 가장 좋은 체크포인트**입니다(마지막 것도 `export/`에 따로 보관).
- 체크포인트: 10만 스텝마다 원자적 저장(임시 파일 → rename), `state.json`에 단계·예산·곡선 저장, `--resume`으로 재개.

## 실행

```bash
npm ci && npm run build:node
pip install -r rl/requirements.txt
python -m rl.imitate all --expert mpc --run il-v1                       # BC + DAgger (~20분)
python -m rl.train_ppo --variant random --steps 2000000 --run ppo-random-v1
python -m rl.train_ppo --variant bc --init rl/runs/il-v1/bc-r0.zip --steps 2000000 --run ppo-bc-v1
python -m rl.train_ppo --variant dagger --init rl/runs/il-v1/bc-r2.zip --steps 2000000 --run ppo-dagger-v1
python -m rl.evaluate --episodes 100                                     # 최종 평가 → public/data/rl/final-eval.json
```
